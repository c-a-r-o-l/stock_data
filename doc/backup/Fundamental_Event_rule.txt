Fundamental Event Token Format — StockGPT Market Language
================================================================================
版本: v1.0
日期: 2026-06-18
来源: doc/Fundamental_Event_Logic.txt (60 events, curated from 90)
================================================================================

Token Format:

    Metric_Severity

- Metric: PascalCase, the fundamental dimension being measured
- Severity: baked into the name — same metric at different thresholds = different events

Duration is NOT part of the token.  Duration is tracked by the CSV columns:
    obs_date       = when the condition was last confirmed
    available_date = when the data became available

The "age" of an event = Today − obs_date (in months).
The system computes this at query time — no need to encode it in the token.

Example:
    EPS_Accelerating          (event name only)
    GM_WideMoat               (event name only)

At query time:
    EPS_Accelerating + obs_date 2026-05-29  →  "1 month old"
    EPS_Accelerating + obs_date 2026-02-28  →  "4 months old"

================================================================================
Frequency — MONTHLY ONLY
================================================================================

Fundamental data is MONTHLY from TradeStation GetFundData().
Fundamentals DO NOT change daily or weekly — only when a new quarterly
filing is ingested.  There is no daily or weekly fundamental event stream.

Output file:  fundamental_event_monthly.txt

CSV format (matching macro_event convention):
    obs_date,available_date,event

Example:
    2026-05-29,2026-06-18,EPS_Accelerating
    2026-05-29,2026-06-18,GM_WideMoat

================================================================================
Severity
================================================================================

Severity IS part of the EventName.
Same metric at different thresholds → different tokens:

    Revenue_Declining      (Rev_Growth < 0%)
    Revenue_Slow           (Rev_Growth 0-10%)
    Revenue_Solid          (Rev_Growth 10-15%)
    Revenue_Strong         (Rev_Growth 15-25%)
    Revenue_Hyper          (Rev_Growth 25-35%)
    Revenue_Explosive      (Rev_Growth > 35%)

    GM_Low                 (GM 0-20%)
    GM_Avg                 (GM 20-30%)
    GM_AboveAvg            (GM 30-40%)
    GM_WideMoat            (GM 40-50%)
    GM_Exceptional         (GM > 50%)

================================================================================
Direction Tokens (for trend/acceleration events)
================================================================================

When a metric has a direction (improving, declining, accelerating, decelerating),
encode the direction in the token:

    EPS_Accelerating       (EPS growth rate increasing)
    Revenue_Accelerating   (revenue growth rate increasing)
    Revenue_Decelerating   (revenue growth rate slowing — EXIT signal)
    GM_Expanding           (gross margin trending up)
    GM_Inflecting          (gross margin turning up after decline)
    Deleveraging           (LT debt/equity improving)
    ROE_Expanding          (ROE trending higher)
    OpMargin_Inflecting    (operating margin in 3-step uptrend)

================================================================================
Don't Split Unnecessarily
================================================================================

When other tokens already diagnose the context, keep one token:

    ROE_High  (not ROE_15, ROE_20, ROE_25)

The Rev_Growth and GM buckets provide the granularity.
Other events can use simpler binary naming.

================================================================================
Point Events
================================================================================

Even "point events" (one-time transitions) use the same format.
The obs_date tells the system how recently the transition occurred:

    Earnings_Turnaround + obs_date 2026-05-29   →  "1 month ago, fresh"
    Earnings_Turnaround + obs_date 2025-11-30   →  "7 months ago, fading"
    Revenue_CycleTurn  + obs_date 2026-04-30   →  "2 months ago"
    CoiledSpring       + obs_date 2026-03-31   →  "3 months ago"

================================================================================
Data Output Format
================================================================================

When generating the fundamental event stream, use CSV matching macro_event
conventions:

    obs_date,available_date,event

- obs_date:       date of the fundamental snapshot (month-end)
- available_date: date when the data became available (~1 month after obs)
- event:          the token (e.g., EPS_Accelerating)

Example:
    2026-05-29,2026-06-18,EPS_Accelerating
    2026-05-29,2026-06-18,Rev_HighGrowth
    2026-05-29,2026-06-18,ROE_High
