第0步：环境准备
================================================================================

你需要:
  - Windows 10/11
  - Python 3.10+
  - Git
  - FRED API Key (免费申请: https://fred.stlouisfed.org/docs/api/api_key.html)
  - 本地ETF月线数据 (C:\ATM\History_3_M\ 目录, 23个ETF的CSV文件)

终端操作:
  cd D:\Projects\Stock_Event1_Macro
  python -m venv .venv
  .venv\Scripts\pip.exe install requests python-dotenv

创建 .env 文件:
  FRED_API_KEY=你的免费key

================================================================================
第1步：下载FRED宏观数据
================================================================================

文件: src/download_macro.py (~400行)

功能: 从FRED API下载约115个宏观指标到 data/ 目录

关键设计决策:
  - 文件名使用类别前缀 (A1_=美联储资产负债表, B_=就业, C_=通胀...)
  - 这样在 data/ 文件夹里按名称排序时, 同类别文件自动分组
  - 延迟0.5秒/请求 (FRED API限制)

运行:
  src\download_macro.bat

验证: data/ 目录应该有 ~115 个CSV文件

================================================================================
第2步：构建宏观-股市逻辑链条 (核心知识库)
================================================================================

文件: src/macro_logic_chains.txt (~2500行)

这是整个项目的"大脑"——每个Event是一个可验证的宏观→股市规律。

2.1 信息来源
  - 学术论文 (Estrella-Mishkin, Hamilton, Leamer, Shiller, Sahm...)
  - 机构研究 (NBER, FRED, NY Fed, Chicago Fed, BofA, Goldman Sachs...)
  - 大师框架 (Dalio, Soros, Druckenmiller, Bacon, Howard Marks...)
  - 深度研究对抗性验证 (5轮, 25个声明中14个存活)

2.2 Event格式 (每个Event一个表格)
  | 字段 | 内容 |
  |------|------|
  | 触发条件 | 精确的量化阈值 |
  | 宏观含义 | 这个条件告诉市场什么 |
  | 对股市影响 | 方向 + 量级 + 历史案例 |
  | 风格因子 | 成长/价值/大小盘/周期/防御 |
  | 逻辑链条 | 因果机制 Step by Step |
  | 失效场景 | 什么条件下这个规律不适用 |
  | 数据需求 | 需要哪个data/文件 |
  | 数据延迟 | T+1(日度)/W+1(每周)/M+1~2(月度)/Q+1~2(季度) |
  | 实证来源 | 论文/研究报告引用 |

2.3 筛选标准
  - 必须有实证数据支撑 (不是理论推测)
  - 必须有回测10年以上的记录
  - 排除纯技术面规律
  - 排除日内高频信号

2.4 附录
  - 附录A: 关键阈值速查表 (极度看涨→极度看跌)
  - 附录B: 大师框架引用索引
  - 附录C: 学术文献引用
  - 附录D: 数据目录 (D0延迟速查, D1 FRED系列, D2 ETF, D3外部源, D4章节矩阵)

================================================================================
第3步：设计Token格式 (对接StockGPT)
================================================================================

协议: EventName_Duration

规则:
  - Duration = round(Today - 观测期结束日期) 用数据自身的频率单位
  - 日度数据用 D (如 BullSteepener_1D)
  - 周度数据用 W (如 Claims_Rising_2W)
  - 月度数据用 M (如 Payrolls_Declining_1M)
  - 季度数据用 Q (如 GDP_Slowing_1Q)
  - Severity 是 EventName 的一部分 (如 VIX_Panic vs VIX_Capitulation)
  - 不要人工拆分Event (如 Fed_Cut 不拆成 Insurance/Recession——其他Event会提供上下文)

输出: 未来每个Event会生成一个token, 如 BullSteepener_1D, SahmRule_3M

================================================================================
第4步：编写Event检测引擎
================================================================================

文件: src/generate_macro_events.py (~950行)

这是把 macro_logic_chains.txt 的知识变成可运行代码。

4.1 输出三个文件
  data/macro_event_daily.txt    — 日度事件 (obs_date,available_date,event)
  data/macro_event_weekly.txt   — 周度事件
  data/macro_event_monthly.txt  — 月度事件

  格式: 一行一个event (不是一行多个event)
  如: 2020-03-01,2020-04-01,VIX_Panic

4.2 数据加载
  - load_fred_csv(): 加载FRED CSV (跳过"."空值)
  - load_etf_csv(): 加载ETF CSV (转换YYMMDD/YYYMMDD日期格式)
  - _map_monthly_to_etf(): 把月度PAYEMS日期映射到ETF月末日期
  - _nearest(data, date, window): 最近日期匹配 (解决不同频率数据对齐)

4.3 关键坑位 (我们踩过的)
  1. GLD ETF是约1/10盎司黄金, 必须×10才是现货金价
  2. SLV ETF约1:1白银, 不需要调整
  3. SPY ≈ SPX/10, Gold/SPY ratio计算需要补偿这个10倍
  4. ETF日期格式: 1994-1999年是6位YYMMDD, 2000+是7位YYYMMDD
  5. BAMLH0A0HYM2 (高收益OAS) 数据只有2023年以后——用BAA10Y (1986+)替代
  6. WALCL/TGA/RRP是周三发布, NFCI是周五——需要_nearest()匹配
  7. FYFSD是年度数据 (财年截止9月30日), 不是月度
  8. 别用TLT ETF——用FRED DGS10做债券数据
  9. ISM PMI是付费的——用INDPRO (工业生产) YoY作为替代
  10. 变量名冲突: cp (Core PCE) 和 cp (Corporate Profits) 会冲突

4.4 事件频率分配
  日度: 国债收益率, VIX, 信用利差, Fed利率, 汇率, 商品价格, 股指
  周度: 初请失业金, Fed资产负债表, NFCI
  月度: 就业, 通胀, 住房, 货币供应, 消费者信心, 板块轮动, Gold/ETF指标

4.5 运行
  src\generate_macro_events.bat

  预期输出: 86种事件类型, ~34,000行
  Daily: 26 types, 24K rows
  Weekly: 16 types, 5K rows
  Monthly: 44 types, 5K rows

================================================================================
第5步：审计与修复
================================================================================

5.1 文档审计 (macro_logic_chains.txt vs 原始论文)
  发现:
  - Event 8 (Fed降息) 回报数字被夸大了 (+34%应为+23%, -38%应为-18%)
  - Event 19 (Sahm Rule) 的"2-5月领先"声明不在原始论文中
  - Event 22 (ISM) 的92.3%精确度在N=13样本下是虚假精度
  → 修复: 拆分Event 8, 修正数字, 添加出处

5.2 代码审计 (generate_macro_events.py vs 文档)
  发现:
  - Event 6 0.94%阈值用了错误的期限利差 (2Y-10Y, 应为3M-10Y)
  - Event 11 缺少30天速度过滤器
  - Event 43 缺少6个月连续条件
  - 17个Event完全缺失
  → 修复: 更正阈值, 添加过滤器, 实现缺失事件

5.3 数据审计 (FRED API可用性)
  发现:
  - VIXCLS 实际上在FRED上可用 (之前错误标记为CBOE专有)
  - CPATAX (企业利润) 实际上在FRED上可用
  - GSCPI 和 CMDI 不在FRED上 (NY Fed直接下载)
  → 修复: 添加15个新FRED系列, 更新数据目录

5.4 代理审计 (替代数据计算)
  发现:
  - Gold/SPY比率有10倍缩放错误 (SPY≈SPX/10未补偿)
  - Fed_Restrictive在高通胀期间产生假阳性
  - 其他8个代理计算正确
  → 修复: 更正阈值8.0, 实现真实利率计算

5.5 历史验证
  Gold/Silver比率 >80 在2020年3月正确触发 (GLD×10/SLV = 113.4)
  BAA10Y正确标记了2008年GFC (6.11% > 5.5%) 和2020年COVID (4.31%)
  Sahm Rule正确触发了所有9次1970年后的衰退

================================================================================
第6步：Event分层 (4层框架)
================================================================================

Layer A: 可直接量化 (有明确数据/阈值/时间)
  例如: BullSteepener, VIX_Panic, SahmRule, OECD_CLI
  实现: 直接的 if 条件检测

Layer B: 可转化量化 (原本是案例, 可构造指标)
  例如: Bacon相关性断裂 → CrossAsset_CorrelationBreakdown
        Carry崩塌 → GlobalCarry_Breakdown
        AQR宏观动量 → MacroMomentum 4主题综合
  实现: 构造代理指标, 转化为可检测的条件

Layer C: 历史验证事件 (不回测不产生信号)
  例如: 1997亚洲危机, 2000互联网泡沫, 2008 GFC, 2020 COVID
  用途: 验证代码在这些日期是否产生了应有的信号

Layer D: 元规则 (不产生Buy/Sell, 而是降低置信度)
  例如: 因子择时大概率无效 (Event 81)
        1/3的预测因子在样本外失效 (Event 86)
  用途: 审计时自动检查, 降低过度依赖宏观择时的置信度

================================================================================
核心教训 (最重要的5条)
================================================================================

1. 永远不要假设一个数据源不可用——测一下FRED API
   (我们错了两次: VIXCLS和CPATAX)

2. ETF代理数据需要单位转换
   (GLD×10=金价, SPY×10≈SPX, 忘了就出10倍错误)

3. 不同频率的数据不能直接比较——用_nearest()做日期对齐
   (WALCL周三 vs NFCI周五, 没有_nearest就匹配不上)

4. 原始论文和流行摘要之间差距巨大
   (Event 8的回报数字被夸大了30-50%)

5. 代码审查不能代替API测试
   (我们以为Gold/Silver>80没触发, 其实是GLD×10修复前)
